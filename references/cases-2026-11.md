# 案例回灌 · EP.03 / EP.04 / EP.05（2026-11，三条竖屏成片）

> 这份文件是「真实成片 → skill 改动」的回灌记录：
> **§1–7 = 0.3.0**，来自 **EP.04「卢特尼克」**（336.6 s / 21 场 / 153 句）和
> **EP.03「黄仁勋·上集」**（326.1 s / 18 场 / 87 句）；
> **§8–12 = 0.4.1**，来自 **EP.05「48 小时四连反转」**（302.7 s / 19 场 / 138 句）。
> 三条都是 1080×1920 / 30 fps / −14 LUFS、字幕不烧、右下圆头像。
> 写在前面：**下面的「用户口径」是原话或原话的直接结论，不是我的总结。**

## 1. 画面里的字：从「全删」到「只标题」

这是这一版最大的一条，因为来回改了两轮：

1. 第一轮用户说「把 EP03 这些字删掉」→ 我把标题/数字/年份/印章/人名全删，做成纯图版。
   **用户真实意思是"删画面里的字"，不是"删项目"**——这条差别让我误删过 0.94 GB（见 §3）。
2. 第二轮用户说「还是要有点文字的，要不然太单一」→ 定稿成**只保留标题层**。

定稿的标题层（现在的实现是 `scene_kit.scene_head`）：

| 项 | 值 |
|---|---|
| 结构 | 每场**一行标题**（微软雅黑 Bold 44 / 米白）+ **一句副标**（25 / 冷灰），可选 |
| 落区 | 只在 `TITLE_BAND`（y 254–360）；内容区 400–1290、**字幕带 1300–1460 一像素不碰** |
| 可读性 | 顶部压一层深色渐隐薄膜（`K.scrim_top()`），照片底上也能读 |
| 装饰 | 左侧 5 px 琥珀竖条，入场时从上往下长出来 |
| 入场 | 每场 `t_in=0.30`、0.55 s 淡入；标题垫一层 55% 黑影，副标入场时轻微上浮 |
| 开关 | `KOUBO_TITLE=mid`（默认，标题+副标）/ `light`（只标题）/ `off`（回纯图） |
| 文案 | `scene_kit.TEXT = {场景名: (标题, 副标)}` 字典，一行一场 |

结论：**竖屏口播的画面文字是"导航"，不是"字幕"**。一屏超过「1 个主信息 + 1 条副信息」就该删；
但一屏都没有字，观众会觉得"这集是不是没做完"。

## 2. EP.04 给的另一条反面经验：底要换

用户对 EP.04 的要求是「跟上一集一样」——同一套大字体系，但**背景要四种底轮换**
（国会山实拍 / 聚光黑底 / 双色章节 / 航线点阵），连续两场不许同一种。
一条 5 分半的片子 21 场，如果底只有一种，观众 90 秒就开始疲劳。
所以排版式时要先排「底的序列」，再往里填内容。

## 3. 一次不可逆的事故（写进铁律）

用户说「把那个 EP03 都删掉吧」。我理解成"删整个项目"，`Remove-Item -Recurse` 删掉
500 个文件 / 0.94 GB，**回收站没进**。用户真实意思是"把视频里的字删掉"。

- 恢复：误删前留的 `_archive/` 备份救回了原片、`final.srt`、`cues.json`、事实核对；
  四个历史成片和全部场景源码**永久丢失**，只能重写。
- 现在的规则：**破坏性指令先复述一遍"我要删的是 X，不是 Y"，等用户确认再动手。**

## 4. 实测参数（可以直接抄）

| 项 | 值 |
|---|---|
| 头部裁切（EP.03 本片实测） | `box=980 @ (590,932)`（默认 520×520 @ (570,838) 装不下这个机位） |
| 圆头像 | 直径 280，圆心 (840,1555)（右距 100 / 下距 345） |
| 内容区 / 字幕带 | x 72–1008 / y 400–1290；字幕带 y 1300–1460 |

| 渲 18 场 | 10 min（`--jobs 4`，CRF 17，含标题层） |
| 合成 324 s | 23 min（本机空闲时 11–20 min，开视频会议能拖到 90 min） |
| 成片 | 326.10 s / 51.3 MB / −14.00 LUFS / TP −1.17 |

## 5. 新增的第六道验收

`assets/pipeline/成片/_模板/03-动画/audit_text_band.py`：把每场按 1 fps 跑一遍，检查**每一个文字包围盒**
都落在 x 72–1008 / y 140–1290 内。它抓的是「标题排到字幕带里」「副标顶出画布右边界」这类
肉眼在小图上看不出来的错。EP.03 18 场跑下来 0 越界，才敢渲。

用法：

```bash
cd 03-动画
python audit_text_band.py            # 全部场景
```

## 6. 素材与研究（这两条片子踩得最疼的地方）

- **人物肖像**：Bing 图片搜索大量串词（返回米老鼠剪纸、蜘蛛侠服装），
  人物图必须过 vision 复核；宁可上"首字母灰卡"，也不要配错人——那是"配图即指控"。
- **来源不可达**：NYT / Seattle Times / Al Jazeera / NBC / AP / Guardian / Truth Social
  在本机连不上（TCP 超时），截图永远抓不到；改用授权转载站（thestar / investing.com / CNBC）
  并保留出处。
- **一手来源**：画面里的"谁干的/哪一天/多少钱"必须能点开原文；报道口径写「据……报道」；
  查不到的不上屏。EP.03 口播里有 4 处归因错误，画面按**修正后**的口径写，字幕留给用户决定。
- **图不能裁**：用户的硬口径是"背景图必须看全"，`photo_card` 一律 `contain`，不裁切。

## 7. 还没解决的

- **词级字幕**：`transcribe.py` 有词级 `words.json`（`segments[].words[].start/end`），但字幕仍按句切（一句一条），长句会偏半句；要逐字卡点得自己按词切 cue。
- **BGM / SFX**：本系列口径是"不加 BGM"，`sfx_build.py` 还是空的（泼冷水低频、铁柜落地、glitch tick 都没做）。
- **模板 vs 项目代码**：标题层已经收进 `scene_kit.scene_head`；`hud` 这类每片重写的零件还没收，
  否则第三个片子还要再写一遍。

# EP.05（2026-11-19）· 第三条成片，v0.4.1 的来源

> 《英伟达 48 小时四连反转》——302.73 s / **19 场** / 138 句 / 1080×1920 / 30 fps / −14.26 LUFS。
> 这一集是「整段不剪 + 四种底 + 上网核对」的最短路径样本，也踩了三个新坑。

## 8. 数据（可直接当工期基线）

| 项 | 值 |
|---|---|
| 原片 | 544×960 / 30 fps / 302.73 s，语音占比 99%，**没有可剪的口误段** |
| ASR | large-v3，345 s，133 段 → 句级 138 条 |
| 剪辑 | **不剪**：`timemap.json` 只写 `output_duration` |
| 超分 | 544×960 → 1080×1920，lanczos + unsharp 0.5，约 8 分钟 |
| 场景 | 19 场 / 302.73 s（平均 16 s 一场，最长 31 s） |
| 渲染 | `build_clips --jobs 5 --crf 17`，**454 s**（12–37 fps/场） |
| 合成 | `compose_final`，9082 帧，**817 s** |
| 成片 | 31.99 MB / −14.26 LUFS / TP −1.79 / LRA 1.90 |

## 9. 这一集新踩的三个坑（已进 pitfalls 35–44）

1. **`bg_frame` 缺失 → 19 场全假失败**。EP.03/EP.04 的工程里背景都提成了模块级
   `def bg_frame(t)`，EP.05 图省事写在 `frame()` 里，`check_layout` 立刻把整张照片底当"内容"，
   每场报 6.7 万像素压圆、13 万像素进字幕带。修法见 pitfalls 35。
2. **`motion.py` 版本错位**。工作区 `管线/scripts/motion.py` 还是 EP04 那份（没有 `text_tracking`），
   第六道验收直接 `AttributeError`。覆盖成 skill 里的版本后通过。
3. **响度被迫换成「增益 + 限幅」**。见 pitfalls 39–42；`loudnorm` 单独用在这条素材上
   要么欠 0.6 dB，要么顶穿 −1.0 dBTP。

## 10. 底序列的排法（比"加字"省力，用户口径「背景多元」）

19 场按「实拍 → 聚光黑底 → 双色章节 → 航线点阵」轮换，**连续两场不许同一种**：

```
photo(国会山) spot duo spot duo spot photo(机房) map duo spot photo(国会山)
duo spot duo photo(卢特尼克) duo spot map photo
```

先排底、再往里填内容——顺序反过来会在排版时反复挪位置。
照片底统一压暗到 `dim=0.86~0.90` + `blur=20~30`，只当纹理用，标题层才读得清。
