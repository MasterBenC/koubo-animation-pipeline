# 版式规范 · 1080×1920 竖屏

所有坐标的唯一真源是 `layout.py`，本文只解释**怎么用**。改版式永远改 `layout.py` 的
`PROFILES[模式]` 那一块，不要在场景里写死，也不要给模块级常量赋值。

## 一、四块地

| 区域 | 范围 | 说明 |
|---|---|---|
| 平台安全区 | x 60–1008，y 140–1460 | 顶栏和底部信息条之外的地方 |
| **标题层** | y 254–360（`TITLE_BAND`） | 只放标题 + 副标；入口 `K.scene_head()` |
| **内容区** | x 72–1008，y 400–1290 | 动画主体必须整个落在这里 |
| **字幕带** | y 1300–1460，整幅宽 | 用户后期统一烧字幕，**动画层一个像素都不许进**（图形也不行） |
| 圆头像 | 圆心 (840,1555)，半径 140 → x700–980 / y1415–1695 | 真实人脸，谁都不许压 |

内容区下沿只有 10px 缓冲（1290–1300），别贴着边排。

两条容易看错的边界：

- 圆头像与字幕带有 45px 视觉重叠、下沿 1695 也超出平台安全区 1460——这是**既定设计**
  （人在最右下角）。字幕带禁区约束的是**动画层**；后期烧字幕避开 x 700–980。
- `K.scrim_top()` 是满幅渐隐膜，① `check_layout` 会提示「安全区外」若干像素，**不判失败**。

## 二、填充原则

旧场景的问题不是"元素不够"，是**摊得太开、只用了画布的一半**。新排法：

1. **横向吃满**：主体横幅落在 x 72–1008（936 宽）。只有单列文字（小标题、注释）可以窄。
2. **纵向重心放 y≈820**：视觉中心比画布正中（960）高一点，因为字幕带把下半屏吃掉了。
3. **下沿尽量到 1250 左右**：判据是 ≥1150（`audit_canvas.py`），低于 1150 就会被读成
   "上面一坨、下面空了"；宽度判据是 ≥80%（对 936）。
4. **不要为了填满而堆**：宁可少一个元素，也不要塞到拥挤。空是有意的，但**空要成组**——
   要么整块留白（如图表下方的呼吸区），要么被图形占住，不要出现"半空不空"的灰区。

## 三、命令（每次改完场景都跑，六道一道不少）

```powershell
# 在 <项目>\03-动画 里跑；脚本自己会找到 管线\scripts，不用设 PYTHONPATH
cd <项目>\03-动画

python check_layout.py s07 --step 0.5      # ①圆侵入必须 0，字幕带必须 0
python check_text.py   s07 --fps 10        # ②文字不许压文字
python audit_band.py   s07                 # ③字幕带内文字必须 0
python audit_canvas.py s07                 # ④宽 ≥80%、下沿 ≥1150
python audit_timing.py s07 --thresh 60     # ⑤节拍 vs 台词（阈值是变化像素数）
python audit_text_band.py s07              # ⑥文字整体出界

# 出静帧/联系表自己看
python <工作区>\管线\scripts\render_scene.py scenes\s07_xxx.py --stills 1,3,6 -o preview\x.png
```

场景参数一律大小写不敏感：`s07` / `S07` / `s07_xxx` / `scenes/s07_xxx.py` 都行。

**③ 与 ⑥ 的分工**：③ 只查字幕带（逐场报压带像素，定位快）；⑥ 查四条边
（上沿 140 / 下沿 1290 / 左右 72–1008，专抓标题层顶出去）。两道都留着。

## 四、节拍纪律（比版式更容易翻车）

动画必须**跟着台词走**，不是按秒均摊。两条硬规则：

1. **新元素出现的时刻 = 对应那句台词的起点 − 0.00~0.15 秒**（视觉略微领先）。
   代码里只有一种写法：`ts = L.lead(t)`（`t + 0.12`）。**`t -= 0.12` 是反的。**
2. **任何一段超过 1.2 秒的画面静止都算缺陷**。尤其结尾：台词还在说重点，画面不能停。

审计命令：

```powershell
python audit_timing.py s11                # 阈值 900；看大动作
python audit_timing.py s11 --thresh 60    # 阈值 60；找"轻动作"和死区
```

`--thresh` 的单位是**变化像素个数**，不是帧、不是秒。
输出是「视觉事件 / 台词」混排的时间表，直接看谁早谁晚。

历史片子里修过的典型毛病（同一个病根：动画按自己的节奏走，没对齐台词）：

| 场次 | 病症 |
|---|---|
| S11 | 11.67s 之后静止 **6.0 秒**，正好在讲"最致命的是 / 四个字不可撤销" |
| S07 | 整段早 1.4 秒 + 尾部静止 3.8 秒 |
| S12 | 10.73s 之后静止 3.1 秒 |
| S10 | 翻页序列晚 2.0 秒 |
| S15 | "反手一刀"早 1.6 秒 |

## 五、已知坑（踩过的）

1. **PIL 的 ImageDraw 在 RGBA 画布上不混色**，是直接覆盖像素。所以 `motion.Canvas` 现在在
   **不透明底图上渲染成 RGB**，透明元素靠 `Canvas._comp()` 混。场景里别再直接
   `c.img.alpha_composite(...)`，用 `c._comp(layer)`。
2. `c.text()` 的 anchor 是 `"la"`（y = 顶边）；`c.text_mixed()` 的 anchor 是 `"ls"`（y = 基线）。
   两者混用会让行距算错。
3. `bahn` 只有数字和西文，画中文会回退到 `yh_b` 并打 WARN（这是正常的，不是错）。
4. 落边元素不要正好压在 1008 / 1290 上，PIL 的抗锯齿会溢出 1–2px，检查脚本会判失败。
   收到 1002 / 1284 更稳。
5. PowerShell 5.1 的 `Get-Content` 默认按 ANSI 读，中文会显示成乱码——**文件本身没问题**，
   用 `python -c "print(open(p,encoding='utf-8').read()[:200])"` 复核。
6. 场次表 `SCENE_SLOTS` / 分段表 `SCHEDULE` 是**单集数据**：装新片时整块换掉，
   否则节拍审计找不到场次、合成会按错的时间轴盖人。
