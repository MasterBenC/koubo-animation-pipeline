# 口播动画片 · 生产手册

> 这份手册记录一条完整竖屏口播动画片的生产流程：从一条原始口播视频，到可发布的 9:16 成片。
> 第一支片子（`口播-01`，Anthropic 招股书拆解，264 秒）是边做边摸索出来的，
> 所有参数、命令、验收标准都已经在实际生产里验证过。下一支片子照这个走，不要重新发明。

---

## 铁律（违反就是返工）

### 字幕一律不烧

**用户手工在剪映里烧字幕**，只有他自己知道每句该断在哪、停留多久、字号多大。
我们**只交付 final.srt**（时间轴对齐好），画面里不许有任何字幕像素。

- 成片 mp4 里不允许出现任何字幕
- ffmpeg 命令禁止用 `subtitles=` / `ass=` / `drawtext=` 去画台词
- 场景动画里写的字是**图形元素**（标题、数字、标签、箭头说明），是画面的一部分，
  不是字幕，也**不要拿它去顶替字幕**——用户烧上去的字会盖在这些位置上，两层字会打架
- 交付时必须写明：「字幕未烧，final.srt 供后期使用」

管线现状（已核对，保持这个状态）：make_srt.py 只生成 .srt 文件，
没有任何脚本把它喂给 ffmpeg。compose_final.py 只做「动画片段 + 人物」的合成。

这条比画面好看优先。宁可少做一个视觉效果，也不要为了补信息量去烧字幕。

## 0. 一句话流程

```
原始口播 → ASR 逐字稿 → 定剪点(EDL) → 粗剪 → 超分 → 定版式 → 逐场做动画
        → 渲染片段 → 合成 + 响度 → 五道自动验收 → 交付（字幕由用户自己烧）→ 发布
```

每支片子的工作量大致是：**ASR 10 分钟 / 剪辑决策 1 小时 / 16 场动画 2–3 天 / 渲染合成 20 分钟**。

## 2. 环境准备（每次开终端都要设）

```powershell
$env:PYTHONPATH="C:\Users\benhu\Desktop\档案001\.pyfix;C:\Users\benhu\Desktop\档案001\管线\scripts;C:\Users\benhu\Desktop\档案001\work\pylibs"
$env:TEMP="C:\Users\benhu\Desktop\档案001\work\tmp"; $env:TMP=$env:TEMP
```

- `.pyfix` 里是兼容垫片（Python 3.14 上有些库要它）
- `work\pylibs` 是本地依赖：numpy / Pillow / cv2 等
- ffmpeg 8.1.2 在 PATH 里

**Windows 上三个反复踩的坑，先说清楚：**

1. **PowerShell 5.1 的 `Get-Content` 默认按 ANSI 读**，中文显示成乱码不代表文件坏了。
   要确认编码用 `python -c "open(p,encoding='utf-8').read()"`。
2. **`[System.IO.File]::WriteAllText` 的相对路径按进程 CWD 解析**，不是当前 PowerShell 目录。
   一律用绝对路径。
3. **`Set-Content -Encoding UTF8` 会写 BOM**，ffmpeg 的 concat 列表带 BOM 会直接报错。
   写文本一律用 `[System.IO.File]::WriteAllText($f,$t,(New-Object System.Text.UTF8Encoding($false)))`。

## 3. 第一步：ASR 与逐字稿

```powershell
python 管线\scripts\transcribe.py "01-原片\01-原片.mp4" -o "01-asr" --model large-v3 --lang zh --threads 16
```

产物：
- `01-asr\逐字稿.md` —— 带时间码的全文，**主要给人和 AI 读**
- `01-asr\words.json` —— 词级时间（做精确卡点用）
- `01-asr\raw.srt` —— 原始字幕
- `01-asr\silences.json` —— 静音检测

**要点**：ASR 不是为了出字幕，是为了**知道每一句话在第几秒**。后面所有动画节拍都从这张表推。

---

## 4. 第二步：剪辑决策（EDL）

口播常见的毛病是：停顿、口误、重复、跑题。先定剪点，再谈动画。

```powershell
python 管线\scripts\build_edl.py --cuts "02-剪辑\cuts.json" --out "02-剪辑\segments.json"
```

剪完必须做一件事：**重新转录，比对相似度**。

```powershell
python 管线\scripts\transcribe.py "02-剪辑\02-粗剪.mp4" -o "02-剪辑\check-asr" --model large-v3
```

`口播-01` 的实测相似度是 **0.968**（去掉 34.09 秒，16 段）。低于 0.95 就要回头看剪点。

然后生成时间映射 `timemap.json`：**原片时间 ↔ 成片时间**。这个文件是后面所有时间轴的换算基准。

## 5. 第三步：画面提升

原始素材是手机竖拍 544×960，要拉到 1080×1920。`口播-01` 用的链路：

```
scale=1080:1920:flags=lanczos,unsharp=5:5:0.5:5:5:0
```

锐化强度是 A/B/C 三档实测选出来的（`renders\up-A/B/C.png`）。**不要直接上强锐化**，人脸会脏。

## 6. 第四步：定版式（最重要的一步）

版式的唯一真源是 `03-动画\layout.py`，**任何场景都不许写死坐标**。改版式只改这一个文件。

### 6.1 四块地（1080×1920）

| 区域 | 范围 | 说明 |
|---|---|---|
| 平台安全区 | x 60–1008，y 140–1460 | 顶栏、底部信息条之外 |
| **内容区** | x 72–1008，y 400–1290 | 动画主体必须整个在这里 |
| **字幕带** | y 1300–1460，整幅宽 | 用户后期统一烧字幕，**一个像素都不许进** |
| 圆头像 | 圆心 (840, 1555)，半径 140 → x700–980 / y1415–1695 | 真实人脸，谁都不许压 |

### 6.2 圆形头像画中画

```
直径 280，圆心 (840,1555) -> 包围盒 [700,1415,980,1695]
白边 2px，蒙版羽化 10，阴影向下偏移 (0,10)，模糊 22
裁切框 520×520，中心 (570,838)     <- 从源画幅里裁头
```

**裁切框为什么是 520、中心为什么是 (570,838)**：这人是坐着说话的，会左右挪。
早先手测 6 帧得出「头中心 (507,749)、头高 384」，结果到片尾他往右挪了 100 多像素，
圆形头像直接切掉半张脸。后来按 6 个时间点逐帧比对（含 t=149.6 这个最偏的时刻），
才定成现在这个「能覆盖全片最大偏移」的框。**换人换片子必须重新标定这一步。**

标定方法（OpenCV 的路子在这台机器上走不通，见第 10 节坑位 12）：
用 ffmpeg 抽 6–8 帧 → 每帧缩到 540×960 叠 120px 网格 → 拼成联系表 → 肉眼读头的位置 →
取「能装下所有时刻」的最小框 → 再放大 4%。

### 6.3 全屏 ↔ 圆头像的转场

`state_at(t)` 返回 `full / pip / to_pip / to_full` 四态。`pip_params(progress)` 一次给出
`(裁切矩形, 落位矩形, 圆角, 羽化)`：progress=0 是整幅人物，=1 是圆头像。

**这里有个必须记住的方向问题**：`state_at` 给的 prog 是「这段过渡已经走了多少」，
所以 `to_full` 要传 `1 - prog`，否则画面会先缩成圆、最后一帧硬跳成全屏。

### 6.4 换新片子时怎么定

1. 先跑 `python 03-动画\measure_head.py`（**注意：这个脚本目前不可用**，见坑位 12），
   或者按 6.2 的手动方法量。
2. 改 `layout.py` 里的 `PIP_*`、`HEAD_*`、`CONTENT`、`SUBTITLE_BAND`。
3. 跑 `python 03-动画\make_check_png.py <成片帧.png> 构图验收.png` 出标注图给用户看。

## 7. 第五步：写场景

### 7.1 一个场景长什么样

```python
# scenes/s07_55cents.py
DURATION = 12.90
W, H = L.W, L.H

def coin(c, t): ...        # 每个视觉元素一个函数
def bar(c, t): ...

def draw(t):
    c = K.canvas(t)                      # 统一背景
    K.chapter(c, t, "01", "利润表 · 底层结构", 220)
    K.headline(c, t, "每赚 1 块钱，5 毛 5 交出去", 282, 54, t_in=0.15)
    coin(c, t); bar(c, t); vendors(c, t)
    return c.finish()

def frame(t): return draw(t)
```

`scene_kit.py` 里有现成的：`canvas / chapter / headline / rule / number / card / strike / cross`。
`motion.py` 里有：`stage / ease_* / spring / Canvas`。

### 7.2 六条硬规则

1. **确定性**：同样的 t 必须出同样的帧，禁止 `random`。要做抖动就用 `t` 的函数或固定种子。
2. **不写死坐标**：全部从 `layout.py` 的常量推。
3. **文字不许进字幕带**：`y ≥ 1300` 是禁区。
4. **不要直接 `c.img.alpha_composite()`**：画布是 RGB，混图层用 `c._comp(layer)`。
5. **`c.text()` 的 anchor 是 `"la"`（y=顶边）**，`c.text_mixed()` 是 `"ls"`（y=基线），混用会算错行距。
6. **中文不要给 `bahn`**：那字体没有汉字，会自动回退并打 WARN（不致命，但说明字体用错了）。
   纯数字/西文用 `bahn`，中文用 `yh` / `yh_b`。

### 7.3 节拍纪律（比版式更容易翻车）

这是 `口播-01` 返工最多次的地方。第一版做出来，画面很漂亮，但**对不上台词**：

- S11 在 11.67 秒之后画面静止了 **6 秒**，而那 6 秒他正在说「最致命的是 / 四个字不可撤销」
- S07 整段比台词**早 1.4 秒**，尾部还静止 3.8 秒
- S10 的翻页晚了 **2 秒**
- S05 的结论句早了 **1.5 秒**

两条规则：

1. **新元素出现的时刻 = 对应台词起点 − 0.00~0.15 秒**（视觉略领先，读起来最舒服）。绝不晚于台词。
2. **超过 1.2 秒的画面静止就是缺陷**。尤其结尾：台词还在讲重点，画面不能停。

怎么量：

```powershell
python 03-动画\audit_timing.py s11            # 阈值 900：看大动作
python 03-动画\audit_timing.py s11 --thresh 60  # 阈值 60：找轻动作和死区
```

输出是「视觉事件 / 台词」混排的时间表，一眼能看出谁早谁晚。

**做节拍的顺序**：先把 `cues.json`（台词时间轴）打印出来，按句子列一个表，
再把每个视觉元素挂到某一句上，最后写代码。**不要先写动画再对时间。**

### 7.4 横向填充原则

旧场景最大的问题是「只用了画布一半」——当年为了给矩形画中画让位排的窄版。
新排法：

1. 主体横幅落在 x 72–1008（936 宽）
2. 视觉中心压到 y≈820（比画布正中高一点，因为字幕带吃掉了下半屏）
3. 下沿尽量到 1250 左右；低于 1150 就会被读成「上面一坨、下面空了」
4. **不要为了填满而堆**：宁可少一个元素，也不要挤。空要成组，不要半空不空

## 8. 第六步：渲染与合成

```powershell
cd 管线\成片\口播-01\03-动画

# 1) 批量渲染片段（16 场约 363 秒，4 并发）
python build_clips.py --force --jobs 4 --crf 17

# 2) 片段 + 人物 → 成片（约 7.2 fps，264 秒片子要 14 分钟）
python compose_final.py --out "..\02-剪辑\04-合成.mp4"

# 3) 响度归一（口播人声满格，峰值压住）
ffmpeg -hide_banner -loglevel error -y -i "..\02-剪辑\04-合成.mp4" `
  -af "volume=7.2dB,alimiter=limit=0.841:attack=4:release=55:level=false" `
  -c:v copy -c:a aac -b:a 192k -ar 48000 -movflags +faststart "..\02-剪辑\05-成片.mp4"
```

**响度标准**：`-14 LUFS / TP ≤ -1.0 dBTP`（短视频平台通用）。
第一版源素材是 -19.2 LUFS / TP +0.4 dBTP（已经削波了），所以先 `volume` 再 `alimiter`。

**注意 `volume` 和 `alimiter` 的顺序不能换**，先提增益再用限制器兜峰值。

## 9. 第七步：五道自动验收（一道都不能省）

```powershell
cd 管线\成片\口播-01\03-动画
$files = Get-ChildItem scenes\*.py | ForEach-Object { "scenes\" + $_.Name }

python check_layout.py @files --step 0.5    # ①越界/压圆/进字幕带
python check_text.py  @files --fps 10       # ②文字重叠
python audit_band.py                        # ③文字进字幕带（逐字精确）
python audit_canvas.py                      # ④画布利用率
python audit_timing.py                      # ⑤节拍 vs 台词
```

| 检查 | 判据 | 不通过的典型症状 |
|---|---|---|
| ① check_layout | `圆侵入=0px`、`字幕带=0px` | 内容压到头像、字被字幕盖 |
| ② check_text | 无重叠 | 两行字叠在一起、字压边框 |
| ③ audit_band | 「字幕带内无文字」 | 标题排到了 y1300 以下 |
| ④ audit_canvas | 宽占 ≥85%，下沿 ≥1200 | 画面只用半边、下半屏空 |
| ⑤ audit_timing | 事件贴着台词、无 >1.2s 死区 | 画面自己走自己的、结尾静止 |

**⑤ 是最容易漏的一道，也是最影响观感的一道。** ①②③④ 都过了，片子看起来还是「不对劲」，
八成是 ⑤ 的问题。

## 10. 坑位清单（全部真实踩过）

### 渲染

1. **PIL 的 `ImageDraw` 在 RGBA 画布上不混色**，是直接覆盖像素。
   表现：淡入变硬切、空进度条画出来是满的、30% 白的填充变成实心。
   解法：`motion.Canvas` 在不透明底图上渲染成 **RGB**，透明元素靠 `_comp()` 混。
2. **`Image.filter(GaussianBlur)` 会把整张图糊掉**，羽化只能作用在**蒙版的 alpha** 上。
   做圆头像时我一开始糊了整张卡片，220px 的圆里脸是虚的。
3. **超采样 2x 再缩回**，文字边缘才干净。直接 1x 画中文会毛。
4. **画 1000×1800 的渐变要按行画**，`ImageDraw.line` 逐行比 `point()` 快一个数量级。

### 版式

5. **落边元素不要正好压在 1008 / 1290 上**，抗锯齿会溢出 1–2px，检查脚本判失败。收到 1002 / 1284 稳。
6. **头像裁切框按单帧测量必翻车**。人说话时会挪 100+ 像素，必须扫全片取并集。
7. **转场方向**：`to_full` 要传 `1 - prog`（见 6.3）。

### 时间

8. **不要先写动画再对时间**，一定先列台词表再挂元素（见 7.3）。
9. **画面静止 6 秒 = 观众划走**。S11 就是这么翻车的。

### 工具链

10. **`curl.exe` 在这台机器的沙箱里连不上 HTTPS**（`SEC_E_NO_CREDENTIALS`），
    出站请求一律用 Python 的 `urllib`。
11. **PowerShell 的双引号 here-string (`@"..."@`) 会解释反引号转义**：
    - `` `n `` 变成真换行、`` `t `` 变成制表符、`` `f `` 变成**换页符**（吃掉后面的 f）、
      `` `a `` 变成**响铃符**（吃掉后面的 a）。
    - 写文档/代码时正文里的反引号（Markdown 行内代码）会被误伤，典型症状是
      「final.srt」变成「inal.srt」、「ass=」变成「ss=」。
    - **解法：凡是正文带反引号或多行内容，一律写成 .py 文件用 `Path.write_text` 写，
      不要在 PowerShell 里拼字符串。**
    - 写多行文本也别用 `Set-Content`（会带 BOM），用 `[System.IO.File]::WriteAllText` +
      真正的换行符。
    - 出过问题的话，用 `python -c "..."` 扫一遍控制字符：
      `[c for c in s if ord(c)<32 and c not in "\n\r\t"]`。
12. **OpenCV 5.0 移除了 `CascadeClassifier`，且新 ONNX 导入器读不了 YuNet 模型**
    （`Can't read ONNX file`，ASCII 路径也一样）。所以 `measure_head.py` **目前是不可用状态**，
    头部标定用手动网格法（6.2）。另外 **cv2 在中文路径下打不开文件**，
    要用 ffmpeg 先抽帧到英文临时目录。
13. **`-shortest` 会按最短的流剪画面**。片尾组件加了定格之后，音效还是 1.5 秒，
    结果 60 帧被剪回 45 帧。**音效长度必须等于总时长**。
14. **`build_clips.py` 的参数是场景 ID**（`S07 S11`），不是文件名；没有 `--only` 这个 flag。
15. **子 agent 修改同一个文件会互相覆盖**。两个 agent 同时改 `s12` 时，文件被连续改写。
    派活前确认目标文件没被别的 agent 占用。

## 14. 和用户协作的节奏

这套流程里最省时间的做法不是「一次做完再给看」，而是**分层确认**：

1. **方向层**：动画方向给 2–3 个方案，用静帧对比图让他选（`DIRECTION.md`）
2. **版式层**：出「构图验收图」（`make_check_png.py`），标出安全区/内容区/字幕带/圆头像
3. **场景层**：先做 2 场试样（一窄一偏），点头后再铺开剩下的
4. **参数层**：圆的大小、位置这类，一次给 3 档实际渲染对比（`pos_options.py` / `size_options.py`），
   不要用文字描述「再大一点」——他没法在脑子里渲染

`口播-01` 光「圆头像大小和位置」就来回改了 4 轮，每次都是一句话描述 + 我猜 + 重出片。
后来改成「一次给 3 档真图」，一轮就定了。
