# 版式与节拍规则

> 版式决定「好不好看」，节拍决定「对不对得上」。后者更容易翻车。

---

## 一、四块地（1080×1920）

| 区域 | 范围 | 说明 |
|---|---|---|
| 平台安全区 | x 60–1008，y 140–1460 | 顶栏、底部信息条之外 |
| **内容区** | x 72–1008，y 400–1290 | 动画主体必须整个在这里 |
| **字幕带** | y 1300–1460，整幅宽 | 用户后期烧字幕，**一个像素都不许进** |
| 圆头像 | 圆心 (840,1555)、半径 140 → x700–980 / y1415–1695 | 真实人脸，谁都不许压 |

内容区下沿留 10px 缓冲（1290–1300）。落边元素不要正好压 1008 / 1290，
PIL 抗锯齿会溢 1–2px，检查脚本判失败——收到 1002 / 1284 稳。

## 二、圆形头像

```
直径 280，圆心 (840,1555)  ->  包围盒 [700,1415,980,1695]
右距 100，下距 345
白边 2px，蒙版羽化 10，阴影向下偏移 (0,10)、模糊 22
裁切框 520×520，中心 (570,838)
```

### 头部标定（换人必做）

**不要用单帧测量。** 人说话时会左右挪 100+ 像素，单帧测出来的框到别的时间点会切掉半张脸。
这个坑直接导致过一版圆头像里只有半张脸。

做法：

1. 用 ffmpeg 从成片里抽 6–8 帧（挑几个他动得最厉害的时刻）
2. 每帧缩到 540×960，叠 120px 网格，拼成一张联系表
3. 肉眼读每帧「头顶 / 下巴 / 左耳 / 右耳」的位置
4. 取能装下**所有时刻**的最小框，中心取中位，边长再放大 4%
5. 把框画到真实帧上，缩成 220px 圆形预览，确认头完整、不贴边

判断标准：头占圆的 75–85%，头顶离圆边留一点空，下巴下面能看到一点肩。

### 全屏 ↔ 圆头像的转场

`layout.state_at(t)` 返回 `full / pip / to_pip / to_full` 四态，
`pip_params(progress)` 一次给出 `(裁切矩形, 落位矩形, 圆角, 羽化)`：
progress=0 是整幅人物，=1 是圆头像。

**方向陷阱**：`state_at` 给的 prog 是「这段过渡已经走了多少」，
所以 `to_full` 必须传 `1 - prog`，否则画面会先缩成圆、最后一帧硬跳成全屏。

## 三、横向填充原则

旧场景最大的毛病是「只用了画布一半」——当年为了给矩形画中画让位排的窄版。
量一下就知道：`audit_canvas.py` 里宽度只占 51–60%，右边全空。

新排法：

1. **主体横幅落在 x 72–1008（936 宽）**。只有单列文字（小标题、注释）可以窄。
2. **视觉重心压到 y≈820**，比画布正中（960）高一点——字幕带吃掉了下半屏。
3. **下沿尽量到 1250**。低于 1150 就会被读成「上面一坨、下面空了」。
4. **不要为了填满而堆**。宁可少一个元素也不要挤。空要成组：
   要么整块留白（图表下方的呼吸区），要么被图形占住，不要「半空不空」的灰区。

两种重排手法：

| 场景类型 | 手法 |
|---|---|
| 图形当主角（剖面图、流程图、对比图） | 直接放大到满幅重画 |
| 数字当主角（一个大数字 + 说明） | 不动主数字，在下方补一块解释性卡片/索引 |

## 四、节拍纪律

第一版做出来画面很漂亮，但**对不上台词**：有的场次在讲最狠的一句时画面静止了 6 秒；
有的整段比台词早 1.4 秒；有的翻页晚了 2 秒。这是返工最狠的地方。

### 两条规则

1. **新元素出现的时刻 = 对应台词起点 − 0.00~0.15 秒**（视觉略领先，读起来最舒服）。
   绝不晚于台词。
2. **任何超过 1.2 秒的画面静止都算缺陷**。尤其结尾：台词还在讲重点，画面不能停。

### 怎么做

**先列台词表，再挂元素，最后写代码。** 反过来必返工。

```
0.00  在招股书和长期承诺条款里面        -> 合同纸铺开
3.04  藏着一份高达5000亿到7500亿的      -> 数字压上来
6.68  为了锁死未来7到10年的算力          -> 时间轴出现
9.50  Anthropic跟各大云厂签下天量采购合同 -> 三家并排
15.22 与融资租赁承诺                    -> 附加条款（新补）
16.56 最致命的是                        -> 红色悬念条（新补）
17.72 四个字不可撤销                    -> 空位，留给下一场
```

### 怎么量

```powershell
python audit_timing.py s11            # 阈值 900：看大动作
python audit_timing.py s11 --thresh 60  # 阈值 60：找轻动作和死区
```

输出是「视觉事件 / 台词」混排的时间表：

```
     16.53s   [动效] 变化 94830px
     16.56s   台词   最致命的是
```

差 0.03 秒 = 视觉领先 3 帧，正好。差 1 秒以上就要改。

### 补尾段

结尾最容易死。几种便宜的补法：

- 把最后一句的字幕做成画面元素（「剩下的 45%，才是经营现金流」）
- 最后 1 秒把画面推向下一场（但不抢下一场的内容）
- 已有元素继续做低频呼吸 / 高光扫过（阈值 60 能看到，阈值 900 看不到）

## 五、字体与文字

| 用途 | 字体名 | 实际文件 |
|---|---|---|
| 纯数字 / 西文 | `bahn` | bahnschrift.ttf（DIN 风格，数字好看） |
| 等宽 / 代码感 | `consola` / `consolab` | consola.ttf / consolab.ttf |
| 中文正文 | `yh` / `yh_b` | msyh.ttc / msyhbd.ttc |

- **中文不要给 `bahn`**：那字体没有汉字，会回退到中文字体并打 WARN。
- `c.text()` 的 anchor 是 `"la"`（y = 顶边）；`c.text_mixed()` 是 `"ls"`（y = 基线）。
  混用会算错行距——这个坑导致过「字压在边框上」。
- 折行：中文按字断，英文只在单词边界断；最后一行不足 4 字要从上一行回借，
  避免「孤字」。
- 放大动画（弹出）要做宽度收敛，否则会顶出内边距。
