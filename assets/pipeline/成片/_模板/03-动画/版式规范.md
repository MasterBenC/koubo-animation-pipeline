## 二、填充原则

旧场景的问题不是"元素不够"，是**摊得太开、只用了画布的一半**。新排法：

1. **横向吃满**：主体横幅落在 x 72–1008（936 宽）。只有单列文字（如小标题、注释）可以窄。
2. **纵向重心放 y≈820**：视觉中心比画布正中（960）高一点，因为字幕带把下半屏吃掉了。
3. **下沿尽量到 1250 左右**：低于 1150 就会被读成"上面一坨、下面空了"。
4. **不要为了填满而堆**：宁可少一个元素，也不要塞到拥挤。空是有意的，但**空要成组**——要么整块留白（如图表下方的呼吸区），要么被图形占住，不要出现"半空不空"的灰区。

## 四、节拍纪律（比版式更容易翻车）

动画必须**跟着台词走**，不是按秒均摊。两条硬规则：

1. **新元素出现的时刻 = 对应那句台词的起点 − 0.00~0.15 秒**（视觉略微领先，读起来最舒服）。
2. **任何一段超过 1.2 秒的画面静止都算缺陷**。尤其结尾：台词还在说重点，画面不能停。

审计命令：
```powershell
python audit_timing.py <场景前缀>           # 阈值 900；看大动作
python audit_timing.py <场景前缀> --thresh 60   # 阈值 60；找"轻动作"和死区
```
输出是「视觉事件 / 台词」混排的时间表，直接看谁早谁晚。

## 六、已知坑（踩过的）

1. **PIL 的 ImageDraw 在 RGBA 画布上不混色**，是直接覆盖像素。所以 `motion.Canvas` 现在在**不透明底图上渲染成 RGB**，透明元素靠 `Canvas._comp()` 混。场景里别再直接 `c.img.alpha_composite(...)`，用 `c._comp(layer)`。
2. `c.text()` 的 anchor 是 `"la"`（y = 顶边）；`c.text_mixed()` 的 anchor 是 `"ls"`（y = 基线）。两者混用会让行距算错。
3. `bahn` 只有数字和西文，画中文会回退到 `yh` 并打 WARN（这是正常的，不是错）。
4. 落边元素不要正好压在 1008 / 1290 上，PIL 的抗锯齿会溢出 1–2px，检查脚本会判失败。收到 1002 / 1284 更稳。
5. PowerShell 5.1 的 `Get-Content` 默认按 ANSI 读，中文会显示成乱码——**文件本身没问题**，用 `python -c "open(...,encoding='utf-8')"` 复核。
